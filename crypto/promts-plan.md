# Крипто-блок: минимальное E2E на Kotlin Multiplatform (Android-first)

## Статус: Ф1–Ф4 выполнены ✅
24/24 JVM-теста, 6/6 на устройстве (эмулятор API 36 + реальное ZENO 1, Android 15), 6/6 Go-теста.

## Продуктовая модель (подтверждена владельцем)
- История сообщений — ТОЛЬКО на устройствах, зашифрована; сервер восстановить не может.
- Сервер хранит лишь: справочник публичных ключей, токены пушей, транзитную очередь
  шифроблобов (TTL 30 дней, лимит 1000/получатель, удаление при доставке).
- Профили, поиск, бэкапы, метаданные на сервере — отсутствуют по построению.
- Следствие модели: потеря устройства без живого второго = потеря истории (лекарство — Ф5).

## Границы папок (после реорганизации)
- `crypto/` — клиентский крипто-модуль KMP: крипта + зашифрованное локальное хранилище.
- `../go/` — сервер: релей + справочник ключей (Go stdlib, ноль криптокода).

## Стеки (зафиксированы)
- Клиент Android: Kotlin + Jetpack Compose + Coroutines/Flow + OkHttp(WS) +
  kotlinx.serialization + наш крипто-модуль. DI ручной.
- Клиент iOS (план): KMP + CryptoKit-actual + Keychain; сборка на macOS-хосте.
- Сервер: Go (статический бинарь) + PostgreSQL (managed, PITR) + Caddy (TLS) +
  1–2 VM + Docker Compose. Без K8s/Redis/NATS до реальной потребности.
- Обоснование сервера: сервер видит HTTP/JSON-контракт, а не платформы; iOS язык
  сервера не меняет. План Б — Kotlin/Ktor, если команда останется чисто Kotlin-овой.

## Криптосхема v1 (аналог sealed box, stateless)
- Пара EC P-256 на устройство; публичный ключ (SPKI 91Б) на сервере, секретный (PKCS8) —
  в клиенте, завёрнут AES-ключом AndroidKeyStore.
- Отправка: ephemeral ECDH → HKDF-SHA256 → AES-256-GCM; AAD = SPKI получателя;
  формат: [SPKI ephemeral 91Б][IV 12Б][шифротекст||тег].
- Сессий и форвард-секреции нет — осознанный потолок; сверка: SafetyCode (6 цифр).
- Wire format платформо-независим: векторные тесты гарантируют байт-в-байт
  совместимость Android/iOS/будущего web.

## Вехи
- ✅ Ф1. Ядро: 15 векторов и атак-тестов (RFC 5869/4231/5903, McGrew–Viega).
- ✅ Ф2. Android: KeyVaultAndroid, AAR без единого стороннего класса, 3/3 на API 36.
- ✅ Ф3. Сервер: релей+справочник (Go), TOFU-пиннинг, TTL+лимит очереди; кросс-стек smoke.
- ✅ Ф4. Локальное хранилище: журнал AES-GCM с AAD=chatId, ключ в AndroidKeyStore-обёртке,
  plaintext на диске отсутствует (проверено тестом), 6/6 на устройстве.
- Ф5 (следующий). Перенос истории device-to-device через QR + зашифрованный канал —
  лекарство от «потерял устройство — потерял историю». Минимум-вариант: новое устройство
  без истории.
- Ф6. Пуши: шифрованный payload (FCM/APNs), plaintext в пуши не уходит; WS-синк.
- Ф7 (опционально). Локальный экспорт истории с паролем.

## Потолки и триггеры миграции (на Rust + UniFFI)
- Нет форвард-секреции: утечка ключа устройства = читается его история.
- TOFU до первой сверки SafetyCode (подмена ключа сервером при первом контакте).
- Триггеры: форвард-секреция / пост-квант / третья платформа.

## Контроль границ
- В release-бинарь крипто-модуля не входит ни одна сторонняя библиотека (AAR проверен).
- kotlin-stdlib (Apache-2.0) — принят; androidx.test/JUnit — только тестовые APK.
- Сервер: хранение в памяти, рестарт теряет транзит — прод-замена Postgres задокументирована.
