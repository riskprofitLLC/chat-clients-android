# План проекта: мессенджер с хранением только на устройствах

## Продуктовая модель (подтверждена владельцем)
- История сообщений и ПРИНЯТЫЕ МЕДИА живут ТОЛЬКО на устройствах, зашифрованные;
  сервер не может восстановить её принципиально.
- Сервер хранит лишь: справочник публичных ключей, токены пушей, транзитную очередь
  шифроблобов (TTL 30 дней, лимит 1000, удаление при доставке) и транзит
  медиа-блобов (TTL 30 дней; клиент скачивает и хранит расшифрованную копию локально).
- iOS-клиент исключён из планов (решение владельца).
- Регистрация: email → 4-значный код на почту (Resend API) → пароль → логин авто-генерируется.
- Публикация: через сайт-визитку (https://ednar.duckdns.org/chat/).

## Стек
- Клиент Android: Kotlin + Jetpack Compose + Coroutines/Flow + OkHttp(WS) + крипто-модуль KMP.
- Клиент Web: TypeScript + vanilla DOM (ноль прод-зависимостей), крипта на WebCrypto, сборка Vite — `clients/web` (план `promts/web-plan.md`, см. также CHANGELOG 0.24.0).
- Сервер: Go + PostgreSQL 16 + Caddy (TLS, Let's Encrypt) + Resend (email).
- Email: Resend API (100 писем/день, CHAT_RESEND_KEY на сервере).

## Деплой (выполнен 2026-10-10)
Сервер: ednar.duckdns.org (адрес панели и IP хоста — вне репозитория)
- Go-релей: systemd, за Caddy, ~2 MB RAM
- PostgreSQL 16: база chat, persistent
- Caddy: TLS (Let's Encrypt, auto-renew), 80 (redirect) + 443 (HTTPS)
- Медиа: /var/lib/chat/media (TTL 30 дней, sweep ежечасно)
- Email: Resend API (CHAT_RESEND_KEY)
- Адрес приложения: https://ednar.duckdns.org
- Сайт-визитка: https://ednar.duckdns.org/chat/

## Фаза G — Read receipts, «Избранное», правка сообщений ✅ (выполнена)
- G0 (фикс): групповые сообщения снова уходят в групповом конверте —
  Outbox строит конверт один раз и шлёт/хранит одинаковые байты
  (ref совпадает у всех сторон; реакции и ответы в группах работали
  со сломанными ref). Аналогично выправлен toggleReaction.
- G1: «Прочитано» — POST /v1/read → WS-кадр `read:<peer>` → синие
  галочки ✓✓ у отправителя (только 1:1; открытие диалога = прочитано).
- G2: «Избранное» — чат с самим собой (self-send kind=chat разрешён);
  fan-out на свои устройства, локальная копия — из outbox; свой логин
  не требует TOFU (устройства сверены при линковке). Также починен путь
  уведомлений о новом устройстве (ранее блокировался self-send-запретом).
- G3: Правка сообщений — TYPE_EDIT-событие (ref цели + готовые байты
  нового контента), применяется к журналу у всех сторон байт-в-байт,
  маркер «изм.», окно 48 ч, только свой текст; у групп конверт цели
  берётся из оригинала (без сайд-эффектов состава). Реакции на старый
  ref снимаются, ts сохранён (позиция и таймеры не страдают).

## Фаза I — Навигация, отложенная отправка, закрепы ✅ (выполнена, живой smoke пройден)
- I1: Поиск в чате — режим подсветки: лента не сжимается, совпадения
  обводятся акцентом, счётчик «n/m» со стрелками и прыжками; ввод нового
  запроса — курсор на ближайшее к низу совпадение (HistoryNav, чистая
  логика позиций reverseLayout: pending + (total-1-pos)).
- I2: «Перейти к дате» — Material-календарь из меню чата, прыжок к
  первому сообщению дня, пустой день — ближайшее старшее; цель
  подсвечивается и гаснет через 1.8 с.
- I3: Отложенная отправка — long-press «отправить» → дата → время;
  Outbox.Entry.sendAt (0 — сразу), flushAll ждёт sendAt; будильник —
  OneTimeWorkRequest «chat-sched-wake» (REPLACE по ближайшему),
  при живом соединении — штатный цикл outbox. В ленте — приглушённый
  пузырь с «Отправится: …» и удалением. Wire и сервер не менялись.
- I4: Закрепы — TYPE_PIN-событие (по образцу TYPE_EDIT, решение
  владельца): {"i":ref,"to":ts,"p":0|1}; не пишется в журнал,
  применяется к per-chat состоянию (ChatPrefs), в группах — внутри
  конверта. Плашка под шапкой, тап — прыжок, ✕ — откреп. Правка
  переносит закреп на новый ref, удаление — снимает. Состояние
  локальное (не переносится линковкой, как пин/мьют).
- Живой smoke (S24 Ultra, Android 16): connected 27/27 вкл. e2e
  pinsend (входящий TYPE_PIN через реальный релей), отложенная
  отправка полным циклом UI, поиск с подсветкой, переход к дате,
  закреп/откреп. Наблюдения: WAL-дубль при убийстве процесса в окне
  append→walDelete; фоновая доставка отложенного на Samsung —
  воркер выходит из замороженного процесса мгновенно, запись уезжает
  после возобновления (будильник WorkManager стартует точно в срок).
